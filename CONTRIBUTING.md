# Contributing to Ajit's Open-Source Projects

Thank you for your interest in contributing. This document provides guidance for contributing to the open-source projects maintained under the `ajit-ai` GitHub account.

## Reporting Bugs

If you encounter a bug in any project:

1. Search existing issues to avoid duplicates.
2. Open a new issue with a clear, descriptive title.
3. Include steps to reproduce, expected behavior, and actual behavior.
4. Note the project, language, and environment where the issue occurred.

## Requesting Features

Feature requests are welcome. When submitting one:

1. Open an issue describing the feature and its intended use case.
2. Explain the problem it solves or the gap it fills.
3. Be open to discussion about scope and approach.

## Discussing Significant Changes

For substantial changes (new features, architectural changes, breaking changes):

1. Open an issue first to discuss the proposal.
2. Wait for feedback before investing significant effort.
3. This helps avoid duplicate work and ensures alignment with project goals.

## Fork and Branch Workflow

1. Fork the repository you want to contribute to.
2. Create a descriptive branch from `main`:
   ```
   git checkout -b feature/my-new-feature
   ```
3. Make your changes in small, focused commits.
4. Keep your fork synchronized with the upstream repository.

## Pull Requests

When submitting a pull request:

1. Provide a clear description of what the PR does and why.
2. Reference any related issues (e.g., "Fixes #42").
3. Keep PRs focused — one logical change per PR.
4. Ensure your code follows the existing style of the project.
5. Be responsive to review feedback.

## Tests and Validation

Where tests exist:

1. Run the existing test suite before submitting.
2. Add tests for new functionality when feasible.
3. Ensure all CI checks pass.

Where no test infrastructure exists, describe how you verified your changes work correctly.

## Documentation Contributions

Improvements to documentation are valuable contributions:

- Fix typos, clarify explanations, or add examples.
- Improve README files, code comments, or inline documentation.
- Ensure code examples are correct and runnable.

## Code Quality Expectations

- Follow the existing code style and conventions of each project.
- Keep changes focused and avoid unrelated formatting changes.
- Write clear commit messages that explain what changed and why.
- Do not include secrets, credentials, or proprietary information.

## Code of Conduct

All contributors are expected to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Questions?

If you have questions about contributing, open an issue with the label "question" in the relevant repository.

Thank you for helping improve these open-source projects.
